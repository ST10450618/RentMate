RentMate UI redesign plan

The app works, but each screen sets its own spacing, buttons and messages, and the look matches what design tools now flag as generated. This plan sets one standard for spacing, type, colour and components, lists the UX principles behind it, and orders the fixes so the most visible ones land before the demo.

Two sources: the ai-design-check checker (141 rules, reads Jetpack Compose) run on app/src/main, and a manual audit of every screen file. The checker needs no API key: npx @enmera/ai-design-check app/src/main.

The standard

One set of tokens, written once in ui/theme, and no literal values in screens. The brand colour stays. The ground, type scale and spacing rules change.

Contrast: lowest text pair is 4.56:1 in light and 4.61:1 in dark (WCAG 2.2 AA asks 4.5:1). Dark values come from the same generator: ground #0C110F, primary #579487.

Type

Seven styles instead of thirteen. Body text moves up to 16 sp, the Android default, because rent and bill amounts are read on small phones. Bundle Public Sans (SIL Open Font License) in res/font, so the app stops using whatever SansSerif each phone ships.

UX principles to implement

Each principle comes from an established source, and each card ends with the concrete fix for RentMate.

Show what the app is doing

Nielsen heuristic 1, visibility of system status

People should never wonder whether a tap worked.

Fix: spinner inside the button while saving, a snackbar on success or failure, an offline banner when there is no network.

Help people recover from errors

Nielsen heuristic 9; WCAG 2.2, 3.3.1 and 3.3.3

An error names the problem in plain words and suggests the fix.

Fix: UX-02. One message per failure type, each with a next step and a Retry action.

Prevent errors first

Nielsen heuristic 5

Stop the mistake before it reaches the server.

Fix: disable Save until the form is valid (RM-0036), number keypad for amounts, date picker with no past dates for due dates.

Undo beats "Are you sure?"

Material 3 snackbar guidance; Raskin, The Humane Interface

Confirmation dialogs get dismissed without reading. Undo lets people act fast and fix mistakes.

Fix: mark paid, delete item and complete chore show a snackbar with Undo for 5 seconds.

Be consistent

Nielsen heuristic 4; Jakob's law

The same thing looks and behaves the same everywhere, and like other Android apps.

Fix: one header, one gutter, two button styles, one list row, one empty state. UX-01.

Recognise, don't recall

Nielsen heuristic 6

Show the information people need instead of making them remember it.

Fix: a colour and initial per housemate on every screen; show whose turn it is and the amount on the row itself.

Answer first, detail after

Inverted pyramid; Material 3 layout guidance

The top of a screen answers the question the person opened it for.

Fix: Home leads with "You owe R 1 245 to Sipho by 30 Nov" and one action.

One main action per screen

Hick's law; ai-design-check One primary action per page

More equal choices take longer to decide between.

Fix: one filled button per screen; the rest are outlined or text buttons.

Big, reachable targets

Fitts's law; Android accessibility, 48 dp; WCAG 2.2, 2.5.8

Small or distant targets are slow and error-prone, especially one-handed.

Fix: every tappable thing at least 48 × 48 dp; main actions at the bottom of the screen where the thumb reaches.

Readable by everyone

WCAG 2.2, 1.4.3 contrast and 1.4.4 resize text

4.5:1 contrast for text, and layouts that survive a 200% font size.

Fix: new palette passes 4.5:1; no fixed heights on text containers; test at the largest font size in Android settings.

Empty states that teach

Material 3 empty state guidance

An empty list explains what goes there and offers the first step.

Fix: "No bills yet. Add rent or electricity to start splitting." with an Add bill button.

Speak the user's language

Nielsen heuristic 2; ai-design-check Sentence case

Use the words housemates use, in sentence case, in their language.

Fix: "Pay Sipho", not "Settle up"; amounts as R 1 245,00 through NumberFormat for en-ZA; no forced uppercase.

Show less at first

Progressive disclosure, Nielsen Norman Group

Keep advanced options out of the way until someone needs them.

Fix: Add Bill defaults to Equally; percentage and exact fields appear only when chosen.

Calm motion

Material 3 motion; WCAG 2.2, 2.3.3

Motion explains a change and finishes fast.

Fix: transitions under 300 ms, no looping animations, and respect the system "Remove animations" setting.

How we roll it out

Tokens first

Change Color.kt, Type.kt and Dimens.kt. Every screen picks up the new ground, type and radii without touching screen code.

About 1 hour · one PR

Shared components

Fix SectionLabel, SecondaryButton, StatusPill, MemberAvatar and ScreenHeader, and add the snackbar host.

About 1.5 hours · one PR

Screen sweep, by owner

Each owner removes literal values, swaps raw buttons and adds snackbar feedback on their screens, following the tables above.

30 to 60 minutes per person, in parallel

Keep it from coming back

Declare the scales so the checker knows them, then run it in Android CI next to lint.

// ai-design-check.json
{ "spacing": 4, "radius": [6, 10, 14, 18],
